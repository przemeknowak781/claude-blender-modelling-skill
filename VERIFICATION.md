## Findings that contradict common assumptions

Each was found by introspection or by a failing test, not by reading docs.

| # | Finding | Evidence |
| --- | --- | --- |
| 1 | **No Bevel node in Geometry Nodes 5.2.** | `RuntimeError` on `nodes.new`; recorded in `api_dump.json` |
| 2 | **`modifier["Socket_N"]` access is REMOVED in 5.2.** Read, write and `.keys()` all raise `TypeError: this type doesn't support IDProperties`. The 5.2 form is `modifier.properties.inputs.<Socket_N>.value`. | T-16 asserts all three raise |
| 3 | **`bl_rna` enum lists are a superset of what is settable.** `FunctionNodeCompare.data_type` advertises 24 values, accepts 11. | harvest records `enum_settable` separately |
| 4 | **The engine enum understates itself.** `enum_items` reports only `BLENDER_EEVEE` at factory startup, yet `BLENDER_WORKBENCH` and `CYCLES` assign fine — while the 4.x `BLENDER_EEVEE_NEXT` raises `TypeError`. | assignment test, `drawing/references/linework.md` |
| 5 | **OBJ operator defaults do not round-trip.** Export and import both at their documented defaults returns the part rotated (Y/Z swapped). Blender-native `forward='Y', up='Z'` on both sides is lossless. | T-19 |
| 6 | **`wm.stl_import(global_scale=...)` writes to OBJECT SCALE**, not the mesh, leaving `obj.scale = 0.001` — antipattern 1 by default. | T-06 |
| 7 | **Manifoldness does not detect flipped normals.** The T-01 fixture reports 0 non-manifold edges, closed, while carrying 234 inconsistently-wound edges. Normal consistency is a third, independent test. | T-01, `cadlib.inconsistent_normal_edges` |
| 8 | **Merge by Distance is necessary but not sufficient.** Welding abutting bodies merges shells and leaves interior walls; the mesh stays non-manifold and the volume reading changes meaning. | T-07 |
| 9 | **A multi-shell self-intersecting cutter makes `EXACT` boolean produce nothing, silently.** No exception. One manifold cutter per boolean. | found while writing T-12 |
| 10 | **Vertex coordinates are float32.** Even at the origin the precision floor is ~1e-7 m; at a 600 km easting a 1 mm feature carries ~0.03 mm of error. | T-14 |
| 11 | **`BMElemSeq` does not support slice steps.** `bm.faces[::4]` raises `TypeError`. | found while writing T-02 |
| 12 | **Changing a custom property does not invalidate its drivers.** The owner must be `update_tag()`-ed too, or the driver silently returns the stale value. | T-17 |

### Specification premises that did NOT reproduce

The task specification stated two things this project could not confirm:

1. *"Socket identifiers for the Compare and Random Value nodes changed in 5.2."*
   In 5.2 they are `A`/`B`/`Result` and `Min`/`Max`/`ID`/`Seed`/`Value`, stable
   across every settable data type. The real subtlety is different: sockets
   vary with **operation** (`EQUAL` adds `Epsilon`) and Random Value swaps
   `Min`/`Max` for `Probability` when `data_type='BOOLEAN'`.
2. *"A new Bevel node in Geometry Nodes 5.2."* There is none (finding 1).

The specification's warning that **"the Python API for Geometry Nodes modifier
properties changed between 5.1 and 5.2"** is confirmed and is finding 2 above —
the most consequential item in this document.

## Maintenance

On every Blender release:

1. Re-run the harvest: `blender --background --factory-startup --python tools/harvest_api.py -- skills/blender-cad-core/references/api_dump.json`
2. Re-run the validator: `python3 tools/validate_identifiers.py`
3. Re-run the suite: `python3 tests/run_evals.py --json tests/report.json`
4. Record the results here with the date and build hash.

Breaking API changes go in a migration table, not a silent edit. The skill's
own version is semantic and independent of Blender's.
